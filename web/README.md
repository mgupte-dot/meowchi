# Meowchi web app

A browser version of Meowchi: record a cat, get a best guess at the sound type and what the cat may want,
and play synthesized sounds to call a cat over. It installs to a phone's home screen and works offline.

This is separate from the Expo app in the repo root and shares no code with it yet. The audio analysis here
(`src/analysis.js`) does more than `lib/moodAnalyzer.ts` because the browser gives it raw audio samples;
the Expo app only sees loudness over time. Porting it means first getting raw samples out of a recording on iOS.

Everything runs on the device. No recording leaves the phone and no AI service is required.

## Build

    npm install -g esbuild        # once
    pip install pillow            # once
    npm install react react-dom   # once, inside web/
    python3 tools/build.py

The result is `dist/`, a static folder. Serve it with `python3 -m http.server -d dist 8000`, or upload it to any
https host (Netlify Drop, Cloudflare Pages, GitHub Pages). Phones only allow the microphone on https.

## Layout

| Path | What it is |
| --- | --- |
| `src/dsp.js` | FFT, filters, resampling, small statistics helpers |
| `src/sounds.js` | The six Call Kitty sounds, synthesized in code |
| `src/analysis.js` | Analysis v2: noise-aware segmentation, YIN pitch tracking, purr-pulse detection, scored classifier |
| `src/needs.js` | The 13 needs, how sound and setting point to them, the on-device line composer, 26 demo clips |
| `src/sprites.js`, `src/sprites.json` | Pixel art data, generated by `tools/gen_sprites.py` |
| `src/components.jsx`, `src/app-logic.jsx`, `src/app-view.jsx` | The React UI |
| `src/style.css` | Styles |
| `index.html`, `config.js`, `sw.template.js` | App shell, the one optional setting, offline cache |
| `bench/` | Benchmarks for the analysis |

The files in `src/` are concatenated in a fixed order by `tools/build.py` into one script. They share one scope and
are not ES modules. `app-logic.jsx` opens the main component and `app-view.jsx` closes it.

## How a reading is produced

1. `analyzeClip` measures the clip: where the sounds are, pitch and its contour, roughness, pulse rate, noise level.
2. `classifySound` scores each sound type (purr, trill, chatter, hiss, yowl, five kinds of meow, grumble) and reports
   a confidence based on how clearly the best match beats the runner-up.
3. `inferNeeds` ranks what the cat may want from the sound type, the measurements, and the optional setting
   ("by the food bowl", "near the litter box" and so on). Each need carries the evidence for it.
4. `composeLine` picks the spoken line from 121 written lines, choosing by setting, then sound type, then urgency.

All four steps are rules written by hand from general cat-behaviour guidance. Nothing is trained on labelled recordings.

## Benchmarks

    node bench/bench.js       # fixed set, six noise conditions, v1 against v2
    node bench/bench2.js      # 330 randomized clips

On the randomized set v2 identifies 329 of 330 clips and v1 190. The clips are synthesized by the benchmark itself,
so the result shows robustness to noise, quiet recordings and choppy sounds. It is not a measure of accuracy on real
cats, which is untested.

## Optional: AI-written lines

`server/translate/` holds a small Cloudflare Worker that asks Claude to write the spoken line. Put its address in
`config.js` to turn it on. Left empty, which is the default, the app uses `composeLine` and makes no network calls.
